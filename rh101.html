Reading the terminal boxes

A line that starts with $ means "type this as a normal user." A line that starts with # at the very front of a command line means "type this as the administrator (root)." In this site, to keep it simple, every # at the start of a line is a comment explaining the next line, and commands that need admin powers begin with sudo.

Part 01 / foundation

Build your practice lab

You cannot practice on paper. You need a Linux machine you are allowed to destroy. A virtual machine is a fake computer running inside your real computer, and you can wipe it and start over in two minutes.

What you need

  • A host computer with at least 8 GB of RAM and 40 GB of free disk. 16 GB RAM is comfortable.
  • Virtualization software. On Windows or Mac use VirtualBox (free). On Linux use KVM with virt-manager (free, faster).
  • An ISO file — the installation disc image — of AlmaLinux 10, Rocky Linux 10, or RHEL 10.
  • Two virtual machines, not one. Some exam tasks involve one machine talking to another (SSH, NFS, file transfer).

Step by step

  1. Download the ISO. Get the "minimal" or "DVD" x86_64 image from almalinux.org or rockylinux.org.
  2. Create the VM. Give it 2 CPUs, 2 GB RAM, and a 20 GB disk. Then add a second empty disk of 10 GB. That spare disk is where you will practice partitions and LVM. This one step saves you hours later.
  3. Install. Choose "Server with GUI" if you want a desktop, or "Minimal Install" to force yourself into the command line. Set a root password. Create a normal user and tick "make this user an administrator" (that puts them in the wheel group).
  4. Take a snapshot the moment the install finishes and name it clean. When you destroy the machine — and you will — roll back to this in seconds.
  5. Log in and install your toolkit using the commands below.
bash — first login
# Who am I, and what version am I running?

cat /etc/redhat-release
uname -r

# Update everything first. -y answers "yes" to every prompt.
sudo dnf update -y

sudo dnf install -y vim nano tmux git wget curl tree bash-completion \
     man-pages man-db policycoreutils-python-utils setroubleshoot-server \

# Turn on the services that must be running for exam tasks
sudo systemctl enable --now atd crond tuned chronyd firewalld
Gotcha

On a truly minimal install, man pages are often stripped out to save space. During the exam the man pages are your only lifeline, so verify now: run man ls. If nothing appears, run sudo dnf install -y man-pages man-db and then sudo mandb.

Part 02 / essential tools

The shell, help, redirection, and grep

The shell is a program that reads what you type, runs it, and shows the result. On Red Hat systems that program is bash. Everything else in this site is typed into bash.

Why a text prompt instead of clicking

A click can only do the one thing the button was built for. A typed command can be saved, repeated, scheduled, sent to a thousand servers, and reviewed by a coworker. That is why servers are administered by typing. It is also why the exam is typed.

bash — moving around
# Where am I? (print working directory)
pwd

# What is here? -l = long details, -a = include hidden, -h = human-readable sizes
ls -lah

# Change directory. ~ means my home folder, .. means one level up, - means "back"
cd /etc
cd ..
cd ~
cd -

# Look at a file three ways
cat /etc/hostname          # dump it all
less /etc/passwd           # scroll it (q quits, / searches)
head -n 5 /var/log/messages
tail -n 20 /var/log/messages
tail -f /var/log/messages  # follow live, Ctrl+C to stop

Getting help without the internet

You get no internet in the exam. You do get the manuals installed on the machine, and they contain the answer to almost every question. Learn to search them now, not on exam day.

bash — built-in documentation
# The manual for a command. Inside: / to search, n for next, q to quit.
man ls

# Search every manual page title by keyword — the killer exam trick
man -k password
apropos "logical volume"

# If -k says "nothing appropriate", the search index is missing. Build it:
sudo mandb

# Manuals come in sections. 1 = commands, 5 = file formats, 8 = admin commands.
man 5 fstab        # the FORMAT of the /etc/fstab file
man 8 useradd

# Example config files and README files shipped with packages
ls /usr/share/doc/
ls /usr/share/doc/chrony/

# Quick built-in help for most commands
ls --help | less
Exam technique

Forgot the exact /etc/fstab column order? man 5 fstab shows it. Forgot how to set password aging? man chage. Forgot which SELinux command sets a port? man semanage-port. The machine already knows; you only have to know how to ask.

Redirection: sending text where you want it

Every command has three channels: input (stdin), normal output (stdout), and error output (stderr). Redirection is plumbing — you point those channels at files or at other commands.

SymbolMeansExample
>Write output to a file, erasing it firstls > list.txt
>>Add output to the end of a filedate >> log.txt
2>Send only errors to a filefind / -name x 2> errors.txt
2>/dev/nullThrow errors in the trashfind / -name x 2>/dev/null
&>Send output and errors to one filescript.sh &> all.log
2>&1Merge errors into normal outputcmd > f.log 2>&1
<Feed a file in as inputsort < names.txt
|Feed one command's output into the nextps aux | grep sshd
teeShow on screen and save to a filecmd | tee out.txt
Gotcha that eats homework

> destroys the file's old contents instantly and without asking. cat a.txt > a.txt empties the file. When you mean "add to", you almost always want >>.

Also: sudo echo "text" > /etc/protected fails, because sudo elevates echo but the > redirect is done by your shell, which is not root. Use echo "text" | sudo tee -a /etc/protected instead.

grep and regular expressions

grep prints only the lines that match a pattern. A regular expression (regex) is a tiny language for describing patterns — "starts with", "ends with", "any digit", "three or more of these".

bash — grep in anger
# Basic: find lines containing "root"
grep root /etc/passwd

# -i ignore case   -n show line numbers   -v show NON-matching lines
grep -in "error" /var/log/messages
grep -v "^#" /etc/ssh/sshd_config | grep -v "^$"   # strip comments and blanks

# -r search a whole directory tree   -l list only file names
sudo grep -rl "192.168.1.50" /etc/

# -E turns on extended regex (or use egrep)
grep -E "^(alice|bob):" /etc/passwd
grep -E "[0-9]{3}-[0-9]{4}" contacts.txt

# -c count matches   -w whole word only   -A/-B/-C show surrounding lines
grep -c "Failed password" /var/log/secure
grep -w "sda" /var/log/messages
grep -C 3 "kernel panic" /var/log/messages
Regex symbols you actually need
  • ^ start of line — ^root
  • $ end of line — bash$
  • . any single character
  • * zero or more of the previous thing
  • + one or more (needs -E)
  • ? optional (needs -E)
More regex
  • [abc] any one of a, b, c
  • [0-9] any digit; [^0-9] any non-digit
  • {2,4} between 2 and 4 repeats
  • | or — (cat|dog)
  • \. a literal dot
  • \b a word boundary

Editing text files with vim

vim is on every Red Hat system, including the exam machine, including rescue mode. You do not need to love it. You need eight keystrokes.

vim — the only eight things you must know
vim /etc/hosts

# You start in COMMAND mode — typing letters runs commands, not text.
i          # enter INSERT mode, now you can actually type
Esc        # leave INSERT mode, go back to COMMAND mode
:w         # write (save)
:q         # quit
:wq        # save and quit  (ZZ does the same)
:q!        # quit and THROW AWAY changes — your escape hatch
dd         # delete the current line
u          # undo
/text      # search for "text", n = next match
:set nu    # show line numbers
Gotcha

If you cannot save and the message says readonly, you opened a system file without sudo. Escape with :q! and reopen with sudo vim. Do not try to force it — :w! on a root-owned file just fails again and burns your time.

Part 03 / essential tools

Files, directories, links, archives

Linux has no C: drive. Everything — every disk, every USB stick, every network share — hangs off one single tree that starts at /, called root.

/etc
Configuration

Text files that control the system. This is where exam answers get saved permanently.

/var/log
Logs

What the system says went wrong. First stop for troubleshooting.

/home
User files

One folder per person. Root's home is /root instead.

bash — creating, copying, moving, deleting
# Make an empty file / update its timestamp
touch report.txt

# Make folders. -p creates every missing parent folder too.
mkdir -p /srv/project/2026/data

# Copy. -r for folders, -p keeps permissions+timestamps, -v shows what happened
cp report.txt backup.txt
cp -rpv /srv/project /srv/project-backup

# Move or rename — same command
mv report.txt final-report.txt
mv final-report.txt /srv/project/

# Delete. -r for folders, -f forces. THERE IS NO RECYCLE BIN.
rm old.txt
rm -rf /srv/project-backup

# Find files — the most useful search tool on the system
find /etc -name "*.conf"
find /home -user alice -type f
find /var/log -size +10M
find / -perm -4000 -type f 2>/dev/null   # every setuid file
find /tmp -mtime +7 -delete              # delete files older than 7 days
The command that ends careers

rm -rf / or a mistyped rm -rf / home/alice (note the space!) will delete the operating system while it is running. There is no undo, no confirmation, no recovery. Before any rm -rf, run the same path with ls first and read what comes back.

Hard links and soft links

A file has two parts: the data on disk, and a name pointing at it. A hard link is a second real name for the exact same data. A soft link (symbolic link) is a little signpost file that just says "look over there instead".

bash — links
# Soft link (symlink): -s. Works across disks, can point at folders.
ln -s /var/log/messages ~/syslog-shortcut

# Hard link: no -s. Same disk only, files only, not folders.
ln /home/alice/data.txt /home/alice/data-alias.txt

# See the difference: link count and the -> arrow
ls -li
131 -rw-r--r--. 2 alice alice   40 Jul 26 09:00 data-alias.txt
131 -rw-r--r--. 2 alice alice   40 Jul 26 09:00 data.txt
277 lrwxrwxrwx. 1 alice alice   17 Jul 26 09:01 syslog-shortcut -> /var/log/messages

# Follow a symlink chain to the real file
readlink -f ~/syslog-shortcut
How to remember it

A hard link is a second front door to the same house — delete one door, the house is still there. A soft link is a sticky note with an address on it — knock the house down and the note now points at nothing (a "dangling" link, shown in red by ls).

Archiving and compressing

tar bundles many files into one file. gzip, bzip2, and xz squeeze a file smaller. tar can call them for you with one flag.

bash — tar, gzip, bzip2
# c = create, x = extract, t = list, v = verbose, f = filename (always last!)
tar -cvf archive.tar /etc/ssh          # bundle, no compression
tar -czvf archive.tar.gz /etc/ssh      # z = gzip   (fast)
tar -cjvf archive.tar.bz2 /etc/ssh     # j = bzip2  (smaller)
tar -cJvf archive.tar.xz /etc/ssh      # J = xz     (smallest, slowest)

# Look inside WITHOUT extracting — always do this first
tar -tvf archive.tar.gz

# Extract here, or extract somewhere specific with -C
tar -xzvf archive.tar.gz
tar -xzvf archive.tar.gz -C /tmp/restore/

# Compress / decompress a single file (the original is replaced)
gzip bigfile.log        #  -> bigfile.log.gz
gunzip bigfile.log.gz
bzip2 bigfile.log
bunzip2 bigfile.log.bz2
Gotcha

tar prints Removing leading '/' from member names and stores paths relatively. That is normal and good — it means extracting will not overwrite /etc by accident. But it also means you must cd / before extracting if you genuinely want files restored to their original absolute location.

Securely transferring files between machines

bash — scp, rsync, sftp
# scp: simple copy over SSH.  -r for folders.  Note the colon.
scp report.txt alice@server2:/home/alice/
scp -r /srv/project alice@server2:/backup/
scp alice@server2:/var/log/messages ./            # pull the other direction

# rsync: smarter — only sends the differences, can resume, shows progress
rsync -avz /srv/project/ alice@server2:/backup/project/
#   -a archive (keeps permissions, times, links)  -v verbose  -z compress
#   TRAILING SLASH MATTERS: src/ copies the CONTENTS; src copies the FOLDER.

# sftp: interactive session
sftp alice@server2
sftp> put report.txt
sftp> get /etc/hosts
sftp> bye

Part 04 / users and groups

Users, groups, passwords, sudo

Linux was built from day one for many people sharing one machine. Every user has a number (UID), belongs to groups, and is allowed to touch only what their identity permits.

The three files that define everyone

/etc/passwd
Who exists

Username, UID, GID, real name, home folder, login shell. Readable by everyone.

/etc/shadow
The passwords

Scrambled passwords plus aging rules. Readable by root only.

/etc/group
Who is on which team

Group name, GID, and the list of extra members.

bash — creating and changing users
# Create a user with a comment (real name) and the default shell
sudo useradd -c "Alice Nguyen" alice

# Create with specific settings all at once
sudo useradd -u 1501 -g developers -G wheel,dba -s /bin/bash -c "Bob Ray" bob
#  -u UID   -g PRIMARY group   -G EXTRA groups   -s login shell

# A service account that must never log in
sudo useradd -r -s /sbin/nologin appsvc

# Set or change a password
sudo passwd alice

# Change an existing user. -a APPEND is critical for -G.
sudo usermod -aG wheel alice        # add alice to wheel, keep her other groups
sudo usermod -s /sbin/nologin bob   # stop bob logging in
sudo usermod -L bob                 # Lock the account
sudo usermod -U bob                 # Unlock it
sudo usermod -md /home/robert -l robert bob   # rename + move home

# Delete. -r ALSO deletes the home folder and mail spool.
sudo userdel -r bob

# Check your work — three ways
id alice
getent passwd alice
groups alice
The classic exam disaster

usermod -G wheel alice without the -a replaces every one of Alice's secondary groups with just wheel. She silently loses access to everything else. Always type usermod -aG. Say it out loud: "A for Add."

Groups

bash — group management
sudo groupadd developers
sudo groupadd -g 5000 dba          # with a specific group ID
sudo groupmod -n devs developers   # rename
sudo gpasswd -a alice devs         # add a member
sudo gpasswd -d alice devs         # remove a member
sudo groupdel dba

# Who is in a group?
getent group devs
devs:x:1002:alice,bob

Password aging

Companies force passwords to expire. The exam will ask you to set exactly this.

bash — chage
# Show current aging settings
sudo chage -l alice

# Must change every 60 days, cannot change again for 7 days,
# warn 5 days before, disable 14 days after expiry
sudo chage -M 60 -m 7 -W 5 -I 14 alice

# Force a password change at next login (the "temporary password" trick)
sudo chage -d 0 alice

# Account stops working entirely on this date
sudo chage -E 2026-12-31 alice

# Set the DEFAULT for future users (edit these files, not just the user)
sudo vim /etc/login.defs      # PASS_MAX_DAYS, PASS_MIN_DAYS, PASS_WARN_AGE
sudo vim /etc/default/useradd # default shell, home base, INACTIVE

Privileged access with sudo

Logging in as root all day is dangerous — one typo destroys the machine. sudo lets a normal user borrow root powers for one command, and logs every use.

bash — sudo configuration
# On Red Hat, membership of the "wheel" group grants full sudo. Simplest answer:
sudo usermod -aG wheel alice

# NEVER edit /etc/sudoers directly. visudo checks your syntax before saving,
# which prevents locking yourself out of root forever.
sudo visudo

# Better practice: drop a separate file in /etc/sudoers.d/
sudo visudo -f /etc/sudoers.d/devteam
/etc/sudoers.d/devteam
# Everyone in the devs group may run everything, after typing their password
%devs   ALL=(ALL)       ALL

# Alice may run these two commands with NO password prompt
alice   ALL=(ALL)       NOPASSWD: /usr/bin/systemctl restart httpd, /usr/bin/dnf

# A helpdesk group that may only manage users
%helpdesk ALL=(ALL)     /usr/sbin/useradd, /usr/sbin/usermod, /usr/bin/passwd
Gotchas

Files in /etc/sudoers.d/ must be mode 0440 and must not contain a dot or tilde in the filename, or sudo ignores them silently. visudo -f handles the permissions for you.

%name means a group; a bare name means a single user. Forgetting the % is a very common mistake.

Giving NOPASSWD on an editor or on /bin/bash is the same as giving away root entirely — the user can just open a root shell from inside it.

Part 05 / security

Permissions, umask, special bits, ACLs

Every file answers three questions for three audiences: can the owner, the group, and everyone else read it, write it, or run it? That is the entire model.

bash — reading ls -l
ls -l /etc/hosts
-rw-r--r--. 1 root root 158 Jul 26 09:12 /etc/hosts
 │└┬┘└┬┘└┬┘  │  └─┬┘ └┬┘
 │ │  │  │   │    │   └── group that owns it
 │ │  │  │   │    └────── user that owns it
 │ │  │  │   └─────────── number of hard links
 │ │  │  └─────────────── OTHERS  may read
 │ │  └────────────────── GROUP   may read
 │ └───────────────────── OWNER   may read and write
 └─────────────────────── type: - file, d directory, l symlink, b block device

The numbers

Add them up
  • 4 = read (r)
  • 2 = write (w)
  • 1 = execute (x)
  • read+write = 6, read+execute = 5, all = 7
Common results
  • 755 rwxr-xr-x — normal program or folder
  • 644 rw-r--r-- — normal file
  • 700 rwx------ — private folder
  • 600 rw------- — private file (SSH keys)
  • 770 rwxrwx--- — shared team folder
bash — chmod, chown, chgrp
# Numeric (absolute) — sets exactly this
chmod 640 secrets.txt
chmod 755 /srv/scripts

# Symbolic (relative) — adjusts what is there
chmod u+x deploy.sh        # give the owner execute
chmod g+w,o-r report.txt   # group can write, others cannot read
chmod a+r public.txt       # everyone can read
chmod -R g+w /srv/team     # recursive, whole tree

# Change the owner and/or the group
sudo chown alice report.txt
sudo chown alice:devs report.txt
sudo chgrp devs report.txt
sudo chown -R alice:devs /srv/team
The rule people forget

On a directory, the letters mean something different: r = list the names inside, w = create or delete entries inside, x = enter the directory and reach things through it. A folder with r but no x shows you a list of names you cannot open. Almost every "permission denied even though I gave read" puzzle is a missing x on a parent folder.

umask — default permissions

umask is a subtraction mask applied to every new file you create. Files start from 666 and folders from 777; the umask bits are removed.

bash — umask
umask               # show current, usually 0022
0022
# 666 - 022 = 644 for new files   |   777 - 022 = 755 for new folders

umask 027           # now: files 640, folders 750 (others get nothing)
umask -S            # show it in letters instead

# Make it permanent for one user
echo 'umask 027' >> ~/.bashrc

# Make it permanent for everyone (system wide)
sudo vim /etc/profile.d/local-umask.sh
#   umask 027

Special permissions: SUID, SGID, sticky

BitNumberOn a fileOn a directory
SUID4000Runs as the file's owner, not as you. This is how passwd lets you edit /etc/shadow.No effect.
SGID2000Runs as the file's group.New files inherit the folder's group. The key to shared team folders.
Sticky1000No effect (ignored).Only the file's owner may delete it. This is why /tmp is safe.
bash — build a proper shared team folder
# The classic exam task: /srv/team is shared by group devs.
# Members can create and edit, but nobody can delete another person's file.
sudo groupadd devs
sudo mkdir -p /srv/team
sudo chgrp devs /srv/team
sudo chmod 2770 /srv/team        # 2 = SGID, 770 = group full, others none
sudo chmod +t /srv/team          # add sticky  -> result is 3770

ls -ld /srv/team
drwxrws--T. 2 root devs 6 Jul 26 09:20 /srv/team
#     ^ s = SGID here          ^ T = sticky (capital T because others have no x)

# Symbolic versions of the same thing
sudo chmod g+s /srv/team
sudo chmod o+t /srv/team

# Find every SUID program on the system (a security audit staple)
find / -perm -4000 -type f 2>/dev/null

ACLs — permissions for one specific person

Standard permissions only handle one owner and one group. When you need "and also let Jane read this, but nobody else", you need an Access Control List.

bash — setfacl and getfacl
# Give one user read+write on one file
sudo setfacl -m u:jane:rw budget.xlsx

# Give a whole group read+execute on a folder
sudo setfacl -m g:auditors:rx /srv/reports

# DEFAULT acl: everything created here LATER inherits this rule
sudo setfacl -m d:u:jane:rw /srv/reports

# Do both at once, recursively
sudo setfacl -R -m u:jane:rwX,d:u:jane:rwX /srv/reports
#   capital X = execute only on folders, not on plain files. Very handy.

# Look at what is set
getfacl /srv/reports

# Remove one entry, or wipe them all
sudo setfacl -x u:jane budget.xlsx
sudo setfacl -b budget.xlsx
Gotcha

A file with ACLs shows a + at the end of its permission string in ls -l: -rw-rw----+. If you are troubleshooting access and see that plus sign, run getfacl — the real answer is hiding in the ACL, not in the numbers.

Also: running chmod on a file with ACLs can quietly clip the ACL "mask" and cut off permissions you thought you granted. Set ACLs after chmod, then re-check with getfacl.

Diagnosing a permission problem

  1. ls -l file — who owns it, what are the bits?
  2. id user — is that user actually in the group you think?
  3. namei -l /full/path/to/file — checks every folder along the way for a missing x. This one command solves most cases.
  4. getfacl file — is an ACL overriding things?
  5. ls -Z file — is SELinux the real cause? (See Part 14.)
  6. lsattr file — is the immutable flag set? chattr -i file removes it.

Part 06 / manage software

dnf, rpm, repositories, Flatpak

You do not download installers on Linux. You ask a package manager, and it fetches the software plus everything that software depends on, verified by a digital signature.

RPM
The package file

One .rpm file = one piece of software plus its metadata.

DNF
The smart manager

Talks to repositories, solves dependencies, then calls rpm.

Repository
The shop

A server (or folder, or DVD) full of RPMs with an index.

bash — everyday dnf
sudo dnf install httpd            # install
sudo dnf install -y vim tmux git  # several, no prompts
sudo dnf remove httpd             # uninstall
sudo dnf update                   # update everything
sudo dnf update httpd             # update one thing

dnf search webserver              # search names and descriptions
dnf info httpd                    # version, size, licence, summary
dnf list installed | grep http    # what is already here
dnf provides */semanage           # WHICH PACKAGE gives me this file? ★

dnf group list                    # bundles of related packages
sudo dnf group install "Development Tools"

# History — and the undo button most people never learn
dnf history
sudo dnf history undo 14          # reverse transaction 14 completely

# Install a local .rpm file (dnf still resolves its dependencies)
sudo dnf install ./package-1.2-3.el10.x86_64.rpm
The single best dnf trick for the exam

dnf provides */command-name. When a command does not exist — "semanage: command not found" — this tells you the package to install. It searches file contents across all repositories. It has rescued more exam candidates than any other command.

rpm — querying what is installed

bash — rpm queries
rpm -qa                     # query all installed packages
rpm -qa | wc -l             # how many?
rpm -q httpd                # is this one installed, and which version?
rpm -qi httpd               # full information
rpm -ql httpd               # list every file it installed
rpm -qc httpd               # list only its CONFIG files ★
rpm -qd httpd               # list only its documentation
rpm -qf /etc/ssh/sshd_config   # which package owns this file? ★
rpm -V httpd                # verify — has anything been modified?

# Peek inside an .rpm file you have not installed
rpm -qlp ./somepackage.rpm

Configuring a repository

systemd timers — the modern cron

A timer unit runs a service unit on a schedule. Timers are on the objective list alongside cron and at. A timer always needs a matching .service with the same base name.

/etc/systemd/system/backup.timer
[Unit]
Description=Run the backup every night at 02:30

[Timer]
OnCalendar=*-*-* 02:30:00
Persistent=true
Unit=backup.service

[Install]
WantedBy=timers.target
bash — timer commands
sudo systemctl daemon-reload

# Test that your schedule string means what you think
systemd-analyze calendar "Mon..Fri 09:00"
systemd-analyze calendar "*-*-* 02:30:00" --iterations=3

# Useful OnCalendar values:
#   hourly | daily | weekly | monthly
#   Mon..Fri 09:00      every weekday at 9am
#   *-*-01 00:00:00     first of every month
#   *:0/15              every 15 minutes
Gotchas

Enable the .timer, not the .service. Enabling the service makes it run once at boot instead of on schedule.

Persistent=true means "if the machine was off when this was due, run it as soon as it comes back". Without it, a missed run is simply skipped.

Forgetting daemon-reload after editing a unit file is the most common reason a change "does nothing".

Part 09 / boot and recovery

The boot process, GRUB, and getting back in

"Interrupt the boot process in order to gain access to a system" is a real, graded objective. Translation: you will be handed a machine whose root password nobody knows, and you must get in.

The five stages

1 · Firmware

UEFI or BIOS wakes up, tests the hardware, finds a bootable disk.

2 · GRUB2

The boot menu. Picks a kernel and passes it options. This is where you break in.

3 · Kernel + initramfs

Kernel loads with a tiny temporary filesystem holding the drivers needed to reach the real disk.

4 · systemd

PID 1 starts, reaches the default target, starts every service.

Resetting a lost root password

Learn this by heart. Do it five times before exam day.

  1. Reboot. At the GRUB menu, press any key fast to stop the countdown.
  2. Highlight your kernel entry and press e to edit it.
  3. Find the long line starting with linux. Go to the end of it and add a space then rd.break.
  4. Press Ctrl+X to boot. You land in a tiny emergency shell, before the real system starts.
  5. Run the commands below.
emergency shell — root password reset
# Your real system is mounted read-only at /sysroot. Make it writable:
mount -o remount,rw /sysroot

# Step into the real system as if it were the whole machine
chroot /sysroot

# Now set the password
passwd root

# ★ CRITICAL: tell SELinux to relabel every file on next boot.
# Skip this and SELinux will block the login you just fixed.
touch /.autorelabel

# Leave the chroot, then leave the emergency shell
exit
exit

# The machine reboots, relabels (this takes a few minutes), reboots again.
The step everyone forgets

touch /.autorelabel. Without it, /etc/shadow keeps the wrong SELinux label, and your brand-new password is rejected at the login screen with no useful error. You will think you did it wrong. You did not — you skipped one line.

Booting into a different target on purpose

GRUB — temporary boot options
# Press 'e' at the GRUB menu and append ONE of these to the linux line:

systemd.unit=rescue.target        # single-user-ish, minimal services
systemd.unit=emergency.target     # bare shell, / read-only
systemd.unit=multi-user.target    # text mode this once
rd.break                          # stop before the real root is handed over
init=/bin/bash                    # last resort: skip systemd entirely

# Then Ctrl+X to boot. None of these persist — they apply to this boot only.

Modifying the bootloader permanently

bash — GRUB configuration
# 1. Edit the settings file
sudo vim /etc/default/grub
#    GRUB_TIMEOUT=5
#    GRUB_CMDLINE_LINUX="rhgb quiet"        <- kernel options go here
#    Removing "rhgb quiet" shows boot messages instead of the splash screen.

# 2. Rebuild the real config (works for BIOS and UEFI on RHEL 9/10)
sudo grub2-mkconfig -o /boot/grub2/grub.cfg

# The easier, safer alternative: grubby edits both for you
sudo grubby --update-kernel=ALL --args="quiet"
sudo grubby --update-kernel=ALL --remove-args="rhgb quiet"
sudo grubby --info=ALL              # list installed kernels + their options
sudo grubby --default-kernel        # which one boots by default
sudo grubby --set-default /boot/vmlinuz-...   # change it

# 3. Reboot and confirm the option actually took effect
cat /proc/cmdline
Gotcha

Editing /etc/default/grub alone changes nothing. The file the machine actually reads is generated. You must run grub2-mkconfig (or use grubby) afterwards, then reboot and verify with cat /proc/cmdline. "I edited the file" is not a finished task.

Diagnosing a slow or failing boot

Part 10 / local storage

Disks, GPT partitions, and LVM

Storage is where most people lose points, because it has the longest chain of steps and every step depends on the one before. Learn the chain as a chain, and it becomes easy.

The chain, in order

Disk → Partition → Physical Volume (PV) → Volume Group (VG) → Logical Volume (LV) → Filesystem → Mount point → /etc/fstab entry.

Analogy: raw land → fenced plots → plots registered with the council → plots merged into one estate → the estate divided into houses of any size → each house furnished → each house given a street address → the address written in the town register so it still exists tomorrow.

bash — look before you touch
lsblk                    # tree of disks, partitions, mount points ★
lsblk -f                 # plus filesystem type, LABEL and UUID ★
sudo fdisk -l            # detailed partition tables
sudo blkid               # UUID and TYPE of every block device
df -h                    # what is mounted and how full
sudo parted -l           # partition table type (gpt vs msdos)

# Disk naming: /dev/sda (SATA/SCSI), /dev/vda (virtual), /dev/nvme0n1 (NVMe).
# Partitions add a number: /dev/sda1, /dev/nvme0n1p1
Before every storage command

Run lsblk and confirm the device name. Partitioning /dev/sda when you meant /dev/sdb destroys the running operating system in under a second. Say the device name out loud before you press Enter.

Creating GPT partitions

GPT is the modern partition table (the objective specifically says GPT). parted is the fastest way; fdisk also handles GPT if you press g first.

bash — parted, non-interactive
# Put a GPT label on a brand-new disk (ERASES the partition table)
sudo parted -s /dev/vdb mklabel gpt

# Create a 1 GiB partition starting at 1 MiB (aligned = fast)
sudo parted -s /dev/vdb mkpart primary 1MiB 1025MiB

# A second partition using the next 2 GiB
sudo parted -s /dev/vdb mkpart primary 1025MiB 3073MiB

# Flag one as an LVM partition (cosmetic but tidy, and expected)
sudo parted -s /dev/vdb set 1 lvm on

# Check, then make the kernel re-read the table
sudo parted /dev/vdb print
sudo partprobe /dev/vdb
lsblk
bash — fdisk, interactive (what to press)
sudo fdisk /dev/vdb

#  g   create a new empty GPT partition table
#  n   new partition  -> accept default number, default first sector,
#                        then type  +1G  for the size
#  t   change type    -> type 30 for "Linux LVM" (or 'L' to list)
#  p   print the table so far
#  d   delete a partition
#  w   WRITE and exit   ← nothing is saved until you press w
#  q   quit WITHOUT saving  ← your undo button

sudo partprobe /dev/vdb

LVM in five commands

bash — build an LVM stack from scratch
# 1. Turn partitions into Physical Volumes
sudo pvcreate /dev/vdb1 /dev/vdb2

# 2. Pool them into a Volume Group named vgdata
sudo vgcreate vgdata /dev/vdb1 /dev/vdb2

# 3. Carve out a Logical Volume
sudo lvcreate -n lvweb -L 800M vgdata
#    -L 800M  absolute size      -l 50%FREE  percentage of free space
#    -l 100%FREE  use everything left

# 4. Put a filesystem on it
sudo mkfs.xfs /dev/vgdata/lvweb

# 5. Mount it (temporarily for now — fstab comes in Part 11)
sudo mkdir -p /web
sudo mount /dev/vgdata/lvweb /web
df -h /web

# Inspect at each layer
sudo pvs   ;  sudo pvdisplay
sudo vgs   ;  sudo vgdisplay
sudo lvs   ;  sudo lvdisplay

Growing a logical volume — the exam classic

bash — extend an LV and its filesystem
# The one-liner that does BOTH the volume and the filesystem:
sudo lvextend -r -L +500M /dev/vgdata/lvweb
#   -r  = resize the filesystem too  ★ this is the flag people forget
#   +500M = add 500 MB.   -L 2G (no plus) = make it exactly 2 GB.

# Or fill every remaining byte of the volume group
sudo lvextend -r -l +100%FREE /dev/vgdata/lvweb

# The manual two-step, if you skipped -r:
sudo lvextend -L +500M /dev/vgdata/lvweb
sudo xfs_growfs /web                  # for XFS: point at the MOUNT POINT
sudo resize2fs /dev/vgdata/lvweb      # for ext4: point at the DEVICE

# Out of room in the volume group? Feed it another disk first.
sudo pvcreate /dev/vdc1
sudo vgextend vgdata /dev/vdc1
sudo vgs
XFS cannot shrink. Ever.

XFS is the RHEL default filesystem and it grows only. If a task says "reduce", the filesystem must be ext4 — and even then you must unmount, run e2fsck -f, then resize2fs to the smaller size before lvreduce. Get the order wrong and you destroy the data. When in doubt, back up and recreate.

bash — removing LVM cleanly (reverse order)
sudo umount /web
sudo lvremove /dev/vgdata/lvweb
sudo vgremove vgdata
sudo pvremove /dev/vdb1 /dev/vdb2
# Remember to delete the /etc/fstab line too, or the next boot will fail.

/etc/fstab — making it survive a reboot

This file is the whole ball game. "Configure systems to mount file systems at boot by UUID or label" is an explicit objective, and every storage task quietly requires it.

bash — the safe fstab procedure
# 1. Get the UUID. Never trust /dev/sdb1 to keep the same name after a reboot.
sudo blkid /dev/vgdata/lvweb
/dev/vgdata/lvweb: UUID="9c1f-...-4d22" TYPE="xfs"

# 2. Back up fstab BEFORE editing. A broken fstab means an unbootable machine.
sudo cp /etc/fstab /etc/fstab.bak

# 3. Add the line (see the format below)
sudo vim /etc/fstab

# 4. Tell systemd about the change
sudo systemctl daemon-reload

# 5. TEST IT. mount -a mounts everything in fstab that is not yet mounted.
#    If this throws an error, fix it NOW — do not reboot.
sudo mount -a
df -h

# 6. Prove it: reboot and check again. This is the actual exam requirement.
sudo reboot

The mistake that costs a whole exam

A typo in /etc/fstab stops the machine from booting. It drops to an emergency shell and asks for the root password. If that happens: log in, run mount -o remount,rw /, fix the typo with vim /etc/fstab, then reboot. Adding nofail to a non-critical entry makes the boot continue instead of stopping — a great safety net for practice.

Swap space

bash — adding swap without rebooting
# Option A: a logical volume as swap
sudo lvcreate -n lvswap -L 512M vgdata
sudo mkswap /dev/vgdata/lvswap
sudo swapon /dev/vgdata/lvswap

# Option B: a plain file as swap (no spare partition needed)
sudo dd if=/dev/zero of=/swapfile bs=1M count=512
sudo chmod 600 /swapfile          #  ★ required, or swapon refuses
sudo mkswap /swapfile
sudo swapon /swapfile

# Check
swapon --show
free -h

# Persist it: add to /etc/fstab
#   UUID=<swap-uuid>   none   swap   defaults   0 0
#   /swapfile          none   swap   defaults   0 0

# Turn it off
sudo swapoff /swapfile

Mounting NFS network shares

bash — NFS client
sudo dnf install -y nfs-utils

# What does the server offer?
showmount -e server1.example.com

sudo mkdir -p /mnt/shared

#   server1.example.com:/export/shared  /mnt/shared  nfs  defaults,_netdev  0 0

An NFS entry in fstab without _netdev can hang the boot: systemd tries to mount before the network exists, then waits, and waits. Always include _netdev for network filesystems.

autofs — mount only when someone looks

sudo dnf install -y autofs

sudo vim /etc/auto.master.d/shared.autofs

firewalld

A firewall decides which network connections are allowed in. firewalld organises rules into zones — named sets of rules for different levels of trust — and lets you allow traffic by service name instead of memorising port numbers.

bash — the everyday five
sudo systemctl enable --now firewalld

firewall-cmd --state                    # running?
firewall-cmd --get-default-zone
firewall-cmd --get-active-zones
sudo firewall-cmd --list-all            # everything about the current zone ★

# Allow a service, permanently, then activate the change
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --reload              #  ★ nothing happens without this

# Allow a raw port number
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --permanent --add-port=5000-5010/udp
sudo firewall-cmd --reload

# Remove things
sudo firewall-cmd --permanent --remove-service=cockpit
sudo firewall-cmd --permanent --remove-port=8080/tcp
sudo firewall-cmd --reload
The number one firewalld mistake

Forgetting --permanent means the rule vanishes at the next reboot — and the exam grades after a reboot. Forgetting --reload means the permanent rule is saved but not active right now. You need both. Type the permanent command, then always type reload. Verify with firewall-cmd --list-all (runtime) and firewall-cmd --permanent --list-all (saved).

bash — zones and sources
firewall-cmd --get-zones
block dmz drop external home internal nm-shared public trusted work

# Move an interface into a zone
sudo firewall-cmd --permanent --zone=internal --change-interface=enp1s0

# Trust a whole network range in a zone
sudo firewall-cmd --permanent --zone=internal --add-source=192.168.10.0/24

# Work inside a specific zone rather than the default
sudo firewall-cmd --permanent --zone=dmz --add-service=http
sudo firewall-cmd --zone=dmz --list-all

# Change the default zone
sudo firewall-cmd --set-default-zone=public

# Rich rule: allow SSH only from one subnet
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" \
  source address="192.168.10.0/24" service name="ssh" accept'

# What services does firewalld already know by name?
firewall-cmd --get-services | tr ' ' '\n' | grep -E "http|nfs|samba"

sudo firewall-cmd --reload
Panic button

sudo firewall-cmd --panic-on blocks every packet instantly. --panic-off restores. Useful during an incident; catastrophic if you are connected over SSH and forget.

Part 14 / security

SELinux without the fear

SELinux is a second layer of security underneath permissions. Even if the file permissions say yes, SELinux can still say no. It scares people, but for the exam it is really six commands.

The mental model

Ordinary permissions ask "who are you?". SELinux asks "what program are you, and is that program allowed to touch this kind of file?". Every file and every process wears a label (a context). A policy lists which labels may interact. The web server is labelled httpd_t; web pages are labelled httpd_sys_content_t; the policy permits that pair and nothing else. So a hacked web server cannot read /etc/shadow even if it somehow becomes root.

bash — modes
getenforce                 # Enforcing | Permissive | Disabled
sestatus                   # fuller report

sudo setenforce 1          # Enforcing  — block and log   (temporary)
sudo setenforce 0          # Permissive — allow but log   (temporary)

# PERMANENT: edit the config file, then reboot
sudo vim /etc/selinux/config
#   SELINUX=enforcing      <- enforcing | permissive | disabled
Gotcha

setenforce does not survive a reboot; /etc/selinux/config does. If a task says "set SELinux to enforcing", do both. And never solve an SELinux problem by disabling SELinux — on the exam that is an automatic loss of points, because the grader checks the mode too.

Seeing and fixing labels

bash — contexts
ls -Z /var/www/html          # file labels
ps -eZ | grep httpd          # process labels
id -Z                        # your own label

# The label looks like:  user:role:TYPE:level
system_u:object_r:httpd_sys_content_t:s0   index.html
#                     ^^^^^^^^^^^^^^^^^^^^  the TYPE is the part that matters

# ★ THE FIX FOR 90% OF SELINUX PROBLEMS:
#   restore whatever the policy says these files SHOULD be labelled
sudo restorecon -Rv /var/www/html

# See what the policy expects for a path
sudo semanage fcontext -l | grep '/var/www'
matchpathcon /var/www/html/index.html
bash — permanent custom labels
# Scenario: web files moved to a non-standard folder /web

# 1. Teach the policy the rule (permanent, written to the policy database)
sudo semanage fcontext -a -t httpd_sys_content_t "/web(/.*)?"

# 2. Apply the rule to files that exist now
sudo restorecon -Rv /web

# Check
ls -Zd /web

# chcon changes a label RIGHT NOW but is wiped by the next relabel.
# Use it for testing only. semanage + restorecon is the real answer.
sudo chcon -t httpd_sys_content_t /web/index.html

# Copying vs moving:
#   cp  -> the copy INHERITS the destination folder's label (usually correct)
#   mv  -> the file KEEPS its old label (usually WRONG) ★ common exam trap
#   cp --preserve=context  keeps the original label deliberately

Booleans — policy on/off switches

bash — setsebool
getsebool -a | head                        # all switches
getsebool -a | grep httpd                  # the ones for the web server
sudo semanage boolean -l | grep httpd_use_nfs   # with descriptions ★

# -P makes it PERMANENT. Without -P it is lost at reboot.
sudo setsebool -P httpd_enable_homedirs on
sudo setsebool -P httpd_can_network_connect on
sudo setsebool -P ftpd_full_access on

getsebool httpd_enable_homedirs

Port labels

SELinux also labels port numbers. Running the web server on port 8080 fails until SELinux is told that 8080 is a legitimate web port.

bash — semanage port
sudo semanage port -l | grep http_port_t
http_port_t   tcp   80, 81, 443, 488, 8008, 8009, 8443, 9000

# Add a port to an existing label
sudo semanage port -a -t http_port_t -p tcp 8080

# Modify (if the port is already claimed by another type)
sudo semanage port -m -t http_port_t -p tcp 8080

# Remove
sudo semanage port -d -t http_port_t -p tcp 8080

# Same idea for SSH on a non-standard port
sudo semanage port -a -t ssh_port_t -p tcp 2222

Reading SELinux denials

bash — troubleshooting
sudo dnf install -y setroubleshoot-server policycoreutils-python-utils

# Recent denials, in plain English with a suggested fix ★

sudo journalctl -t setroubleshoot --since "10 min ago"

# Raw denial records

sudo grep -i denied /var/log/audit/audit.log | tail

# A denial line names the process (scontext) and the target (tcontext).
# Read those two labels and the answer is usually obvious.

# Full relabel of the whole system on next boot (slow, but the big hammer)
sudo touch /.autorelabel && sudo reboot
The SELinux decision tree

1. Is it really SELinux? Put it in permissive (setenforce 0), retry. If it works now, yes it was. Put it straight back to enforcing.
2. Wrong file label? → restorecon -Rv, or semanage fcontext -a for a non-standard path.
3. A feature that is switched off? → setsebool -P.
4. A non-standard port? → semanage port -a.
Those four cover essentially everything RHCSA will ask.

Part 16 / remote access

SSH and key-based login

SSH is an encrypted remote terminal. Everything a real administrator does happens through it. "Configure key-based authentication for SSH" is a graded security objective.

bash — connecting
ssh alice@server2.example.com
ssh -p 2222 alice@server2            # non-standard port
ssh alice@server2 'df -h'            # run one command and come straight back
ssh -v alice@server2                 # verbose — tells you WHY it failed

# First connection asks you to trust a fingerprint; it is stored here:
cat ~/.ssh/known_hosts

# If a machine is rebuilt, the key changes and SSH refuses loudly. Fix:
ssh-keygen -R server2.example.com

Key-based authentication, step by step

  1. Make a key pair on the machine you are sitting at. You get two files: a private key (never leaves your machine, never shown to anyone) and a public key (safe to hand out).
  2. Copy the public key to the server you want to reach.
  3. Log in with no password.
  4. Optionally, turn off password logins entirely so only keys work.
bash — the whole procedure
# 1. Generate. ed25519 is modern and short; rsa -b 4096 also fine.
ssh-keygen -t ed25519 -C "alice@laptop"
#    Press Enter for the default path ~/.ssh/id_ed25519
#    A passphrase is recommended in real life; blank is fine in the lab.

# 2. Copy the PUBLIC key to the server (this does the permissions correctly)
ssh-copy-id alice@server2.example.com

# 3. Test
ssh alice@server2.example.com     # should not ask for a password

# Doing step 2 by hand, if ssh-copy-id is unavailable:
cat ~/.ssh/id_ed25519.pub | ssh alice@server2 \
  "mkdir -p ~/.ssh && chmod 700 ~/.ssh && \
   cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
Permissions gotcha

SSH refuses keys if the permissions are too loose — and it tells you nothing useful, it just asks for a password again. Required: ~/.ssh is 700, ~/.ssh/authorized_keys is 600, the private key is 600, and the home directory itself must not be group-writable. Also check SELinux: restorecon -Rv ~/.ssh. When key login "mysteriously" fails, it is one of these four things.

/etc/ssh/sshd_config — hardening
PermitRootLogin no              # nobody logs in directly as root
PasswordAuthentication no       # keys only  ← test keys FIRST!
PubkeyAuthentication yes
AllowUsers alice bob            # only these accounts may connect
Port 22
MaxAuthTries 3
ClientAliveInterval 300
bash — apply and verify safely
# Check the file for syntax errors BEFORE restarting the service
sudo sshd -t

sudo systemctl reload sshd

# ★ Keep your current session open and test with a SECOND terminal.
#   If you locked yourself out, the open session can still undo it.

# Non-standard port? Two more steps or nothing connects:
sudo semanage port -a -t ssh_port_t -p tcp 2222
sudo firewall-cmd --permanent --add-port=2222/tcp
sudo firewall-cmd --reload

# Watch login attempts
sudo journalctl -u sshd -f
sudo tail -f /var/log/secure

Gotchas that waste hours

cron has almost no PATH. Your script works by hand and silently fails from cron. Always use full paths: /usr/bin/tar, not tar. Or set PATH=/usr/local/bin:/usr/bin:/bin at the top of the crontab.

The % character is special in crontab lines — it becomes a newline. Escape it: date +\%F.

Output goes to email you will never read. Redirect it somewhere real: >> /var/log/myjob.log 2>&1.

Day-of-month and day-of-week are OR, not AND. 0 0 13 * 5 runs on the 13th and every Friday, not only Friday the 13th.

The service must be enabled. A perfect crontab with crond stopped runs nothing at all.

Part 18 / shell scripts

Writing bash scripts

A script is a text file full of commands. The exam objective asks for four specific skills: conditions (if, test, [ ]), loops (for), script inputs ($1, $2), and using the output of commands inside a script.

bash — the three steps to any script
# 1. Write it
vim /usr/local/bin/hello.sh

# 2. Make it executable
chmod +x /usr/local/bin/hello.sh

# 3. Run it
/usr/local/bin/hello.sh
bash /usr/local/bin/hello.sh     # works even without +x

# /usr/local/bin is already in PATH, so you can then just type: hello.sh

Script skeleton

skeleton.sh
#!/bin/bash
# ↑ the "shebang" — tells Linux which interpreter to use. Line 1, always.

# Safety rails, strongly recommended:
set -euo pipefail
#  -e  stop immediately if any command fails
#  -u  stop if I use a variable that was never set (catches typos)
#  -o pipefail  a pipeline fails if ANY stage fails, not just the last

# Variables: no spaces around the = sign
NAME="world"
TODAY=$(date +%F)          # $( ) captures a command's output
COUNT=$(ls /etc | wc -l)

# Always quote when you use them

Conditions

conditions.sh
#!/bin/bash

# File and directory tests
if [ -f /etc/passwd ]; then  echo "it is a regular file";  fi
if [ -d /var/log ];    then  echo "it is a directory";     fi
if [ -e /tmp/x ];      then  echo "it exists";             fi
if [ -r /etc/shadow ]; then  echo "I can read it";         fi
if [ -w /tmp ];        then  echo "I can write there";     fi
if [ -x /usr/bin/ls ]; then  echo "it is executable";      fi
if [ -s /var/log/messages ]; then echo "not empty";        fi

# Numbers:  -eq -ne -lt -le -gt -ge
COUNT=12
if [ "$COUNT" -gt 10 ]; then
    echo "more than ten"
elif [ "$COUNT" -eq 10 ]; then
    echo "exactly ten"
else
    echo "fewer than ten"
fi

# Strings:  =  !=  -z (empty)  -n (not empty)
NAME="alice"
if [ "$NAME" = "alice" ]; then echo "hi alice"; fi
if [ -z "$MISSING" ];     then echo "that variable is empty"; fi

# Combine:  && and   || or   ! not
if [ -f /etc/fstab ] && [ -r /etc/fstab ]; then echo "readable file"; fi

# Test the SUCCESS of a command directly (no brackets)
if systemctl is-active --quiet sshd; then
    echo "sshd is running"
else
    echo "sshd is DOWN"
fi

# case — cleaner than a stack of elifs
case "$1" in
    start)   echo "starting" ;;
    stop)    echo "stopping" ;;
    status)  echo "checking" ;;
    *)       echo "Usage: $0 {start|stop|status}"; exit 1 ;;
esac
Bracket gotchas

You need spaces inside the brackets: [ "$x" = "y" ] works, ["$x"="y"] is an error. Use -eq for numbers and = for text — mixing them gives wrong answers silently. And always quote variables, or an empty value turns [ $x = y ] into [ = y ], which is a syntax error.

loops.sh

    echo "Round ${i}"
done

for FILE in /etc/*.conf; do
    echo "Found: ${FILE}"
done

# Every argument the script was given ("$@" = all of them, safely quoted)
for ARG in "$@"; do
    echo "Argument: ${ARG}"
done

while read -r LINE; do
    echo "Service: ${LINE}"

while IFS=: read -r NAME _ UID _; do
    [ "$UID" -ge 1000 ] && echo "Regular user: ${NAME} (${UID})"

until ping -c1 -W1 server2 &>/dev/null; do

    sleep 2
done

# $0 = the script's own name
# $1 $2 $3 = the first, second, third argument

Complete example 1 — bulk user creation

/usr/local/bin/bulk-users.sh
#!/bin/bash
#
# Create users listed in a text file, one username per line.
# Usage:  sudo ./bulk-users.sh users.txt devs
#
set -uo pipefail

USERFILE="${1:-}"
GROUP="${2:-}"

# --- checks -------------------------------------------------------
if [ "$#" -ne 2 ]; then
    echo "Usage: $0 <file-of-usernames> <group>" >&2
    exit 1
fi

if [ "$(id -u)" -ne 0 ]; then
    echo "ERROR: run this with sudo." >&2
    exit 1
fi

if [ ! -f "$USERFILE" ]; then
    echo "ERROR: file '$USERFILE' not found." >&2
    exit 1
fi

# --- make sure the group exists ------------------------------------
if ! getent group "$GROUP" >/dev/null; then
    echo "Group '$GROUP' does not exist. Creating it."
    groupadd "$GROUP"
fi

# --- do the work ---------------------------------------------------
CREATED=0
SKIPPED=0

while read -r USERNAME; do
    # skip blank lines and comments
    [ -z "$USERNAME" ] && continue
    case "$USERNAME" in \#*) continue ;; esac

    if id "$USERNAME" &>/dev/null; then
        echo "  skip   ${USERNAME} (already exists)"
        SKIPPED=$((SKIPPED + 1))
        continue
    fi

    useradd -G "$GROUP" -s /bin/bash "$USERNAME"
    echo "ChangeMe123!" | passwd --stdin "$USERNAME" >/dev/null
    chage -d 0 "$USERNAME"           # force change at first login
    echo "  create ${USERNAME}"
    CREATED=$((CREATED + 1))
done < "$USERFILE"

echo
echo "Done. Created: ${CREATED}   Skipped: ${SKIPPED}"
exit 0

Complete example 2 — health check

#!/bin/bash
#
# Quick system health report. Exits non-zero if anything looks wrong.
# Usage:  ./healthcheck.sh [disk-percent-threshold]
#
set -uo pipefail

THRESHOLD="${1:-80}"
PROBLEMS=0
SERVICES=(sshd crond firewalld chronyd)

line() { printf '%s\n' "------------------------------------------"; }

echo "System health report — $(hostname) — $(date '+%F %T')"
line

# --- uptime and load ------------------------------------------------
echo "Uptime  : $(uptime -p)"
echo "Load    : $(cut -d' ' -f1-3 /proc/loadavg)  (cores: $(nproc))"

# --- memory ----------------------------------------------------------
MEM_FREE=$(free -m | awk '/^Mem:/ {printf "%.0f", $7/$2*100}')
echo "Mem free: ${MEM_FREE}%"
if [ "$MEM_FREE" -lt 10 ]; then
    echo "  WARNING: less than 10% memory available"
    PROBLEMS=$((PROBLEMS + 1))
fi
line

# --- disks -----------------------------------------------------------
echo "Filesystems over ${THRESHOLD}% full:"
FOUND=0
while read -r USE MOUNT; do
    USE_NUM="${USE%\%}"
    if [ "$USE_NUM" -ge "$THRESHOLD" ]; then
        echo "  ${MOUNT} is ${USE} full"
        FOUND=1
        PROBLEMS=$((PROBLEMS + 1))
    fi
done < <(df -hP | awk 'NR>1 && $1 !~ /tmpfs/ {print $5, $6}')
[ "$FOUND" -eq 0 ] && echo "  none — all good"
line

# --- services --------------------------------------------------------
echo "Service status:"
for SVC in "${SERVICES[@]}"; do
    if systemctl is-active --quiet "$SVC"; then
        printf "  %-12s running\n" "$SVC"
    else
        printf "  %-12s NOT RUNNING\n" "$SVC"
        PROBLEMS=$((PROBLEMS + 1))
    fi
done
line

# --- failed units and recent errors ----------------------------------
FAILED=$(systemctl --failed --no-legend | wc -l)
echo "Failed systemd units: ${FAILED}"
[ "$FAILED" -gt 0 ] && PROBLEMS=$((PROBLEMS + FAILED))

ERRORS=$(journalctl -p err -b --no-pager 2>/dev/null | wc -l)
echo "Errors this boot    : ${ERRORS}"
line

if [ "$PROBLEMS" -eq 0 ]; then
    echo "RESULT: healthy"
    exit 0
else
    echo "RESULT: ${PROBLEMS} problem(s) found"
    exit 1
fi

/usr/local/bin/sysreport.py
#!/usr/bin/env python3
"""System report using only the Python standard library.
Usage:  ./sysreport.py [--threshold 80]
"""
import argparse
import os
import shutil
import socket
import subprocess
from datetime import datetime

SERVICES = ["sshd", "crond", "firewalld", "chronyd"]


def run(cmd):
    """Run a command, return (exit_code, stdout)."""
    p = subprocess.run(cmd, shell=True, capture_output=True, text=True)
    return p.returncode, p.stdout.strip()


def mount_points():
    """Read real mount points out of /proc/mounts."""
    skip = {"proc", "sysfs", "devtmpfs", "tmpfs", "cgroup2", "devpts", "securityfs"}
    points = []
    with open("/proc/mounts") as fh:
        for line in fh:
            device, mount, fstype = line.split()[:3]
            if fstype not in skip and device.startswith("/"):
                points.append(mount)
    return sorted(set(points))


def uptime_text():
    with open("/proc/uptime") as fh:
        seconds = float(fh.read().split()[0])
    days, rem = divmod(int(seconds), 86400)
    hours, rem = divmod(rem, 3600)
    return f"{days}d {hours}h {rem // 60}m"


def memory_percent_free():
    info = {}
    with open("/proc/meminfo") as fh:
        for line in fh:
            key, value = line.split(":", 1)
            info[key] = int(value.split()[0])
    return info["MemAvailable"] / info["MemTotal"] * 100


def main():
    ap = argparse.ArgumentParser(description="Quick system report")
    ap.add_argument("--threshold", type=int, default=80,
                    help="warn when a filesystem is this %% full")
    args = ap.parse_args()

    print(f"Host    : {socket.gethostname()}")
    print(f"Time    : {datetime.now():%Y-%m-%d %H:%M:%S}")
    print(f"Uptime  : {uptime_text()}")
    print(f"Load    : {os.getloadavg()}  (cores: {os.cpu_count()})")
    print(f"Mem free: {memory_percent_free():.1f}%")
    print("-" * 52)

    print("Disk usage")
    problems = 0
    for mount in mount_points():
        try:
            total, used, free = shutil.disk_usage(mount)
        except PermissionError:
            continue
        percent = used / total * 100 if total else 0
        flag = "  <-- WARNING" if percent >= args.threshold else ""
        print(f"  {mount:<22} {percent:5.1f}%  "
              f"{free // (1024**3):4d} GiB free{flag}")
        if percent >= args.threshold:
            problems += 1
    print("-" * 52)

    print("Services")
    for svc in SERVICES:
        code, _ = run(f"systemctl is-active --quiet {svc}")
        state = "running" if code == 0 else "NOT RUNNING"
        print(f"  {svc:<12} {state}")
        if code != 0:
            problems += 1
    print("-" * 52)

    print(f"Problems found: {problems}")
    raise SystemExit(1 if problems else 0)


if __name__ == "__main__":
    main()

Example 2 — user account auditor

/usr/local/bin/useraudit.py
#!/usr/bin/env python3
"""Audit local accounts. Flags things a security review would flag.
Run with sudo so /etc/shadow can be read.
Usage:  sudo ./useraudit.py [--json]
"""
import argparse
import json
import os
import sys


def read_passwd(path="/etc/passwd"):
    users = []
    with open(path) as fh:
        for line in fh:
            if not line.strip() or line.startswith("#"):
                continue
            f = line.rstrip("\n").split(":")
            if len(f) < 7:
                continue
            users.append({
                "name": f[0], "uid": int(f[2]), "gid": int(f[3]),
                "comment": f[4], "home": f[5], "shell": f[6],
            })
    return users


def read_shadow(path="/etc/shadow"):
    """Returns {username: {'locked': bool, 'no_password': bool, 'max_days': str}}"""
    data = {}
    try:
        with open(path) as fh:
            for line in fh:
                f = line.rstrip("\n").split(":")
                if len(f) < 5:
                    continue
                pw = f[1]
                data[f[0]] = {
                    "locked": pw.startswith(("!", "*")),
                    "no_password": pw == "",
                    "max_days": f[4] or "never",
                }
    except PermissionError:
        print("WARNING: cannot read /etc/shadow — run with sudo", file=sys.stderr)
    return data


def audit(users, shadow):
    findings = []
    for u in users:
        s = shadow.get(u["name"], {})
        issues = []

        if u["uid"] == 0 and u["name"] != "root":
            issues.append("EXTRA UID 0 ACCOUNT — investigate immediately")
        if s.get("no_password"):
            issues.append("empty password")
        if u["uid"] >= 1000 and u["shell"].endswith(("bash", "sh", "zsh")) \
                and s.get("max_days") == "never":
            issues.append("password never expires")
        if u["uid"] >= 1000 and not os.path.isdir(u["home"]):
            issues.append(f"home directory missing ({u['home']})")

        if issues:
            findings.append({"user": u["name"], "uid": u["uid"], "issues": issues})
    return findings


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--json", action="store_true", help="machine-readable output")
    args = ap.parse_args()

    users = read_passwd()
    shadow = read_shadow()
    regular = [u for u in users if u["uid"] >= 1000 and u["name"] != "nobody"]
    findings = audit(users, shadow)

    if args.json:
        print(json.dumps({"regular_users": len(regular),
                          "findings": findings}, indent=2))
        return

    print(f"Accounts total : {len(users)}")
    print(f"Regular users  : {len(regular)}")
    for u in regular:
        state = "locked" if shadow.get(u["name"], {}).get("locked") else "active"
        print(f"  {u['name']:<16} uid={u['uid']:<6} {state:<8} {u['shell']}")

    print("\nFindings")
    if not findings:
        print("  none — nothing suspicious")
    for f in findings:
        print(f"  {f['user']} (uid {f['uid']})")
        for issue in f["issues"]:
            print(f"      - {issue}")


if __name__ == "__main__":
    main()

Example 3 — log analyser for failed logins

/usr/local/bin/failedlogins.py
#!/usr/bin/env python3
"""Count failed SSH logins by source IP, newest journal data.
Usage:  sudo ./failedlogins.py --since "1 day ago" --top 10
"""
import argparse
import re
import subprocess
from collections import Counter

PATTERN = re.compile(
    r"Failed password for (?:invalid user )?(?P<user>\S+) "
    r"from (?P<ip>\d+\.\d+\.\d+\.\d+)"
)


def journal_lines(since):
    cmd = ["journalctl", "-u", "sshd", "--since", since, "--no-pager"]
    result = subprocess.run(cmd, capture_output=True, text=True)
    if result.returncode != 0:
        raise SystemExit(f"journalctl failed: {result.stderr.strip()}")
    return result.stdout.splitlines()


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--since", default="1 day ago")
    ap.add_argument("--top", type=int, default=10)
    args = ap.parse_args()

    ips, users = Counter(), Counter()
    for line in journal_lines(args.since):
        m = PATTERN.search(line)
        if m:
            ips[m.group("ip")] += 1
            users[m.group("user")] += 1

    total = sum(ips.values())
    print(f"Failed SSH logins since {args.since}: {total}\n")

    if not total:
        print("Nothing to report.")
        return

    print(f"Top {args.top} source addresses")
    for ip, count in ips.most_common(args.top):
        bar = "#" * min(count, 40)
        print(f"  {ip:<18} {count:>5}  {bar}")

    print(f"\nTop {args.top} targeted usernames")
    for user, count in users.most_common(args.top):
        print(f"  {user:<18} {count:>5}")

    print("\nSuggested block command for the worst offender:")
    worst = ips.most_common(1)[0][0]
    print(f"  sudo firewall-cmd --permanent --add-rich-rule="
          f"'rule family=\"ipv4\" source address=\"{worst}\" reject'")
    print("  sudo firewall-cmd --reload")


if __name__ == "__main__":
    main()

Part 21 / diagnosis

Key troubleshooting playbooks

Troubleshooting is not magic. It is a short list of questions asked in the right order. Here are the playbooks for the failures you will actually meet.

Playbook 1
A service will not start
  1. systemctl status name -l — read the actual error, do not skim it.
  2. journalctl -xeu name — the full story with hints.
  3. Config broken? Most services have a test flag: sshd -t, httpd -t, nginx -t, named-checkconf.
  4. Port already taken? ss -tulpn | grep :PORT.
  5. SELinux? ausearch -m AVC -ts recent, or test with setenforce 0 then put it straight back.
  6. Permissions on its files or directories? ls -l, ls -Z.
  7. Dependency not running? systemctl list-dependencies name.
Playbook 2
The machine will not boot
  1. Read the last message on screen. It usually names the culprit.
  2. Dropped to emergency shell after an fstab edit? mount -o remount,rw /, fix /etc/fstab, reboot. This is the most common cause by far.
  3. No GRUB menu? Boot the install media in rescue mode and reinstall GRUB.
  4. Kernel panic? At GRUB, pick an older kernel from the menu.
  5. Once you are in: journalctl -b -1 -p err to see what the failed boot complained about.
  6. Boot slow, not broken? systemd-analyze blame.
Playbook 3
"Disk full" but it does not look full
  1. df -h — which filesystem, and is it really at 100%?
  2. df -i — inodes. Millions of tiny files exhaust inodes while space remains.
  3. du -sh /* 2>/dev/null | sort -h then walk down into the biggest.
  4. sudo lsof +L1 — deleted files still held open by a process. The space returns only when that process is restarted. Classic with log files.
  5. journalctl --disk-usage then journalctl --vacuum-size=200M.
  6. Old kernels eating /boot: sudo dnf remove --oldinstallonly.
Playbook 4
Cannot reach the network
  1. ip a — do I have an address at all? Is the interface UP?
  2. ip r — is there a default route?
  3. ping -c2 <gateway> — can I reach the door?
  4. ping -c2 1.1.1.1 — can I reach the outside world?
  5. ping -c2 redhat.com — if this is the only failure, it is DNS.
  6. nmcli connection show — is the profile active, with autoconnect on?
  7. Reaching a service but refused? Check the firewall on the far machine and the SELinux port label.
Playbook 5
"Permission denied" that makes no sense
  1. namei -l /path/to/file — a missing x on any parent folder blocks everything below it.
  2. id user — group membership only applies after a fresh login.
  3. getfacl file — look for the + in ls -l.
  4. ls -Z and ausearch -m AVC -ts recent — SELinux.
  5. lsattr file — immutable (i) blocks even root. Clear it with chattr -i.
  6. Mounted read-only? mount | grep " on /path ".
Playbook 6
The system is crawling
  1. uptime — compare load average against nproc.
  2. ps aux --sort=-%cpu | head and --sort=-%mem.
  3. free -h — is it swapping? Heavy swap use feels like a dead machine.
  4. iostat -x 2 3 — is the disk the bottleneck (%util near 100)?
  5. dmesg -T | tail — hardware errors, OOM killer activity.
  6. Calm it down: renice the hog, or kill it, then find out why it misbehaved.

The five commands to run when you have no idea

bash — the universal opening move

journalctl -p err -b            # 2. what errors happened this boot
df -h && df -i                  # 3. is anything full
free -h && uptime               # 4. memory and load

Part 22 / judgement

Pros, cons, and the gotchas that cost points

Every tool on RHEL is a trade-off. Knowing the trade-offs is what separates someone who memorised commands from someone who can actually run a server.

ChoiceProsConsThe gotcha
XFS RHEL default, very fast on big files, scales to petabytes, quick to create Cannot be shrunk, ever Any task that says "reduce this filesystem" cannot be done on XFS. Use ext4 or recreate.
ext4 Grows and shrinks, decades of tooling, forgiving Slower with very large files, lower limits than XFS Shrinking requires unmount + e2fsck -f + resize2fs before lvreduce. Wrong order = data loss.
LVM Resize online, span disks, snapshots, add capacity with no downtime One more layer to learn and to break Deleting an LV without removing its fstab line makes the next boot fail.
Plain partitions Simple, visible, nothing to misconfigure Fixed size, cannot span disks partprobe after changes, or the kernel keeps using the old table.
SELinux enforcing Contains a compromised service even if it gets root Blocks legitimate setups until labelled correctly Disabling it "to fix" a problem loses exam points and real security. Use permissive to diagnose only.
firewalld Zones, service names, runtime vs permanent, safe to experiment Extra concepts on top of nftables --permanent without --reload means the rule is saved but not active. You need both.
cron Universally understood, five fields, easy to read Almost no environment, poor logging, misses runs if the machine is off Empty PATH. Use absolute paths, and escape % as \%.
systemd timers Journal logging, dependencies, catch-up on missed runs, testable schedules Two files instead of one line Enable the .timer, not the .service, and run daemon-reload.
dnf Solves dependencies, verifies signatures, full undo history Needs a working repository and network A repo file must end in .repo, and baseurl must point at the folder containing repodata.
Flatpak Newest desktop apps, sandboxed, cannot break system libraries Large downloads, duplicated runtimes, desktop-focused Now on the RHEL 10 objectives — know remote-add, install, list, uninstall.
SSH keys No password crosses the network, cannot be brute-forced Lose the private key and you lose access Wrong permissions on ~/.ssh (700) or authorized_keys (600) silently fall back to a password prompt.
ACLs Fine-grained, per-user exceptions Invisible unless you look for the +; easy to forget A later chmod can clip the ACL mask and quietly revoke access.
sudo Least privilege, full audit trail in /var/log/secure Badly written rules give away root by accident Edit only with visudo. Files in sudoers.d need mode 0440 and no dots in the name.
Persistent journal Logs survive a crash — exactly when you need them Uses disk space Create /var/log/journal and set Storage=persistent, then restart journald. Cap it with SystemMaxUse.

The twelve gotchas that cost the most points

01

start without enable. The service runs today and is gone after the reboot. Always systemctl enable --now.

02

usermod -G without -a. Wipes every other secondary group. Always -aG.

03

Mount without fstab. Works now, absent after reboot. And always mount -a to test before rebooting.

04

firewall-cmd without --permanent, or without --reload. You need both, every time.

05

setsebool without -P. The boolean resets at reboot and the service breaks again.

06

Forgetting touch /.autorelabel after a root password reset. Login fails and you will not know why.

07

lvextend without -r. The volume is bigger; the filesystem is not. df shows no change.

08

Editing /etc/default/grub and never running grub2-mkconfig. Nothing takes effect.

09

Editing a unit file or fstab without systemctl daemon-reload.

10

mv instead of cp into a service directory. The old SELinux label travels with the file. Run restorecon.

11

Group added, but not logged out. New group membership only applies to a fresh login session.

12

Never rebooting. The exam grades a rebooted machine. Reboot with time to spare and re-verify everything.

The persistence checklist

Before you call any task finished, ask: service enabled? firewall permanent + reloaded? SELinux boolean with -P? mount in fstab? setting in the config file, not just the running system? Five questions, ten seconds, most of the marks.

Part 24 / the day itself

Exam-day strategy

First five minutes
  • Read every task before starting any.
  • Note which tasks depend on others (users before permissions; storage before mounting).
  • Set the root password task first if there is one — everything else needs it.
  • Confirm you can install packages; if not, fix the repository first.
Middle
  • Do the tasks you know cold, fastest first. Points are points.
  • Verify each one immediately, with a different command.
  • Stuck? Note it and move on. Come back later.
  • Use man -k rather than guessing. The docs are allowed and they are on the machine.
Last thirty minutes
  • Reboot. Really.
  • Re-verify every single task after the reboot.
  • Run the persistence checklist: enabled, permanent, -P, fstab, config file.
  • systemctl --failed and journalctl -p err -b for anything you broke.
Things that turn a pass into a fail

Disabling SELinux to make something work. Leaving the machine unable to boot. Setting a root password the grader cannot use. Locking yourself out of SSH. Forgetting that a task said "and configure it to start at boot".

Things worth doing early

Take one minute to run sudo dnf install -y policycoreutils-python-utils setroubleshoot-server. If a later task needs semanage or an SELinux diagnosis, you have already paid the cost. Also check that man -k works — run sudo mandb if it does not.
