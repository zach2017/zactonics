Safety rule

Commands such as rm -rf, mkfs, fdisk, parted, pvcreate, and edits to /etc/fstab can destroy data or stop booting. Read the device name twice. Take a snapshot first.

Core skill 1

Shell, files, text, and documentation

The shell is a text-based control desk. You type a command, the shell starts the requested program, and the program returns an answer or an error.

Command shape

command option target

Example: ls -l /var/log. The command is ls, the option is -l, and the target is /var/log.

Absolute path

Starts at the root /, like a full street address: /etc/ssh/sshd_config.

Relative path

Starts from your current folder, like directions from where you stand: ../notes.txt.

Everyday file commands

GoalCommandVerificationGotcha
Show current folderpwdRead the printed pathKnow where you are before deleting
List hidden filesls -laNames beginning with a dot appear.* patterns can match more than expected
Create foldersmkdir -p lab/{input,output}find lab -maxdepth 2 -type dBrace expansion happens in the shell
Copy safelycp -a source/ backup/diff -qr source backup/sourceA trailing slash can change the result
Move or renamemv old.txt new.txtls -l new.txtMay overwrite an existing target
Remove a filerm -i old.txttest ! -e old.txt && echo goneThere is no normal command-line recycle bin
Find large filesfind /var -type f -size +100M -printdu -h FILEPermission errors are normal outside your access
Read documentationman systemctlSearch inside man with /wordPress q to quit

Pipes and redirection

A pipe is like passing a worksheet from one student to the next. The first command creates output. The second command filters or changes it.

# Replace a file with standard output
printf "alpha\nbeta\n" > names.txt

# Add to the end instead of replacing
echo "gamma" >> names.txt

# Send error messages to a separate file
find /root /tmp -name "*.conf" 2> errors.log

# Send both normal output and errors to one file
some-command > all-output.log 2>&1

# Pass output through a filter
journalctl -p err | grep -i "network"

# Count matching lines
grep -E '^(root|student):' /etc/passwd | wc -l

Archives and compression

# Create a gzip-compressed archive
tar -czvf etc-backup.tar.gz /etc

# List the archive without extracting it
tar -tzvf etc-backup.tar.gz | head

# Extract into a chosen directory
mkdir -p restore
tar -xzvf etc-backup.tar.gz -C restore

# bzip2 version
tar -cjvf logs.tar.bz2 /var/log

Hard links and symbolic links

Hard link

Another name pointing to the same file data. It normally cannot cross file systems and should not be used for directories.

ln report.txt report-hard.txt
ls -li report*

Symbolic link

A shortcut storing a path. It can cross file systems, but it breaks if the target path disappears.

ln -s /srv/reports/latest.txt latest
readlink -f latest

Core skill 2

Users, groups, permissions, and sudo

A user is an identity. A group is a team. Permissions are the keys that decide who may read, change, or run something.

User lifecycle

# Create a group and user
groupadd appteam
useradd -m -G appteam student1
passwd student1

# Inspect the result
id student1
getent passwd student1
getent group appteam

# Set password aging
chage -M 90 -m 1 -W 14 student1
chage -l student1

# Lock and unlock
usermod -L student1
usermod -U student1

# Remove the user and home directory
userdel -r student1

Permission math

r = 4, w = 2, x = 1. Add the numbers for user, group, and others.

  • 755 = owner can read/write/run; everyone else can read/run
  • 640 = owner can read/write; group can read; others get nothing
  • 700 = only the owner has access
chown student1:appteam report.txt
chmod 640 report.txt
stat report.txt
namei -l /path/to/report.txt

Default permissions and umask

The umask removes permission bits from the normal starting permissions. Regular files usually start from 666 and directories from 777 before the mask is applied.

# Display the current mask
umask

# Use a private mask in this shell
umask 077

# Test the effect
touch private.txt
mkdir private-dir
ls -ld private.txt private-dir

ACLs: extra keys for named users

An Access Control List, or ACL, adds permissions for a specific user or group without changing the main owner and group fields.

# Give user auditor read access
setfacl -m u:auditor:r report.txt

# Display ACL entries
getfacl report.txt

# Set a default ACL on a directory
setfacl -m d:g:appteam:rwx /srv/project
getfacl /srv/project

Safe sudo configuration

Use visudo. It checks the file before saving so one typing mistake is less likely to break all administrator access.

# Open a separate rule file safely
visudo -f /etc/sudoers.d/appteam

# Example rule: appteam may restart httpd
%appteam ALL=(root) /usr/bin/systemctl restart httpd

# Protect the file
chmod 440 /etc/sudoers.d/appteam

# Validate every sudoers file
visudo -c

# Test what the current user may run
sudo -l

Core skill 3

Packages, repositories, RPM, and Flatpak

A package is a labeled box of software files. A repository is a trusted warehouse of packages plus a catalog describing them.

Use DNF for normal work

dnf repolist
dnf search "web server"
dnf info httpd
dnf install -y httpd
dnf history
dnf remove httpd
dnf clean all
dnf makecache

Use RPM for package facts

rpm -q bash
rpm -qi bash
rpm -ql bash | head
rpm -qf /usr/bin/grep
rpm -V bash

rpm -V verifies package-owned files. Output means something differs from the package record; it does not automatically mean an attack.

Create a local repository file

sudo tee /etc/yum.repos.d/training.repo > /dev/null <<'EOF'
[training-base]
name=Training Base Repository
baseurl=http://repo.example.test/rhel10/baseos/
enabled=1
gpgcheck=0
EOF

dnf clean all
dnf repolist
dnf makecache
Real-world gotcha: gpgcheck=0 is easy for a closed practice lab but weak for production. Real systems should verify signed packages using trusted GPG keys.

Flatpak basics

flatpak remotes
flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
flatpak search text-editor
flatpak install flathub org.gnome.TextEditor
flatpak list
flatpak uninstall org.gnome.TextEditor

Core skill 4

Services, processes, performance, and systemd

A process is a running program. A service is a long-running helper, such as SSH or a web server. Systemd is the manager that starts and watches many services.

Systemd command pattern

# Read current state
systemctl status sshd
systemctl is-active sshd
systemctl is-enabled sshd

# Change current state
systemctl start sshd
systemctl stop sshd
systemctl restart sshd
systemctl reload sshd

# Change boot-time behavior
systemctl enable sshd
systemctl disable sshd

# Start now and enable for boot in one command
systemctl enable --now sshd

# Find failures
systemctl --failed
journalctl -u sshd --since today

Processes

ps aux --sort=-%cpu | head
ps -eo pid,ppid,user,%cpu,%mem,stat,cmd
top
pgrep -a sshd
kill PID
kill -TERM PID
kill -KILL PID

Try TERM before KILL. TERM asks a process to clean up. KILL stops it immediately and may leave unfinished work.

Priority and tuning

nice -n 10 long-command
renice 15 -p PID
tuned-adm list
tuned-adm active
tuned-adm profile balanced
tuned-adm verify

A higher nice number means “be nicer to other work” and usually gives the process less CPU priority.

Create a small systemd service

sudo tee /etc/systemd/system/hello-admin.service > /dev/null <<'EOF'
[Unit]
Description=Write a training message to the journal
After=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/bin/logger "Hello from the RHCSA lab"
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now hello-admin.service
systemctl status hello-admin.service
journalctl -u hello-admin.service

Core skill 5

Logs and a repeatable troubleshooting method

Troubleshooting is not random guessing. Use the same order each time: understand the symptom, collect facts, change one thing, verify, and record the result.

1. StateWhat exactly is broken?
2. ScopeOne user, one service, or the whole host?
3. EvidenceStatus, logs, ports, disk, memory, permissions.
4. Small fixChange one cause, not five settings.
5. ProveTest now, after logout, and after reboot.

Journal commands

journalctl -b                    # Current boot
journalctl -b -1                 # Previous boot
journalctl -p err..alert         # Serious messages
journalctl -u sshd               # One service
journalctl --since "30 minutes ago"
journalctl --since today --until now
journalctl -f                    # Follow new messages
journalctl --disk-usage

Make the journal persistent

mkdir -p /var/log/journal
systemd-tmpfiles --create --prefix /var/log/journal
systemctl restart systemd-journald
journalctl --flush
ls -ld /var/log/journal

Common failure playbooks

A service will not start
  1. Run systemctl status NAME --no-pager -l.
  2. Read journalctl -u NAME -b --no-pager.
  3. Check the configuration with the service’s validation tool, such as sshd -t or httpd -t.
  4. Check whether the port is already used: ss -lntup.
  5. Check file ownership, mode, SELinux context, and disk space.
  6. Fix one cause, restart, and verify with status plus an actual client test.
The disk is full 
df -hT
df -ih
du -xhd1 / | sort -h
du -xhd1 /var | sort -h
find /var -xdev -type f -size +500M -ls
lsof +L1

Gotcha: A deleted file may still use space while a process keeps it open. lsof +L1 finds deleted-but-open files.

“Permission denied” 
id
namei -l /full/path/to/file
ls -lZ /full/path/to/file
getfacl /full/path/to/file
getenforce
ausearch -m AVC -ts recent

Check normal Linux permissions first, then ACLs, then SELinux. Do not “fix” the issue by turning SELinux off.

High CPU or memory use 
uptime
free -h
vmstat 1 5
ps aux --sort=-%cpu | head
ps aux --sort=-%mem | head
top
journalctl -p warning --since "1 hour ago"

A high load average does not always mean CPU trouble. Processes waiting for slow disk can also increase load.

Collect a support report 
dnf install -y sos
sos report
ls -lh /var/tmp/sosreport-*

A sos report gathers system facts and logs. Review company policy before sending it because reports can contain hostnames, addresses, configuration, and other sensitive details.

Core skill 6

Networking, DNS, SSH, and file transfer

Think of an IP address as a building number, a route as the road map, DNS as a contact list, and a port as a numbered door.

Read the network before changing it

ip -brief address
ip route
nmcli device status
nmcli connection show
hostnamectl
resolvectl status 2>/dev/null || cat /etc/resolv.conf
ss -lntup

Create a static NetworkManager connection

# Replace enp1s0 and the addresses with your lab values.
nmcli connection add type ethernet \
  con-name lab-static \
  ifname enp1s0 \
  ipv4.method manual \
  ipv4.addresses 192.168.56.20/24 \
  ipv4.gateway 192.168.56.1 \
  ipv4.dns "192.168.56.1 1.1.1.1" \
  connection.autoconnect yes

nmcli connection up lab-static
nmcli connection show lab-static
ip -brief address show enp1s0
ip route
Remote-session gotcha: Changing the active interface can disconnect SSH. In a real environment, use console access, a timed rollback, or a second management path.

Network troubleshooting ladder

  1. 1. Link: ip link and nmcli device status
  2. 2. Address: ip -brief address
  3. 3. Route: ip route get 8.8.8.8
  4. 4. Local service: ss -lntup
  5. 5. Name lookup: getent hosts example.com or dig example.com
  6. 6. Application: curl -v http://server:port/
  7. 7. Security: firewall, SELinux, service binding, and upstream rules

SSH keys

# On the client
ssh-keygen -t ed25519
ssh-copy-id student@server-b
ssh student@server-b

# Secure copy
scp report.txt student@server-b:/tmp/

# Copy a directory efficiently
rsync -av --progress project/ student@server-b:/srv/project/

# Validate the server configuration before restart
sshd -t
systemctl reload sshd

Core skill 7

Firewalld and SELinux

The firewall controls network doors. SELinux controls what processes may do after they are inside the machine. They solve different problems, and both may need correct settings.

Firewalld

firewall-cmd --state
firewall-cmd --get-active-zones
firewall-cmd --list-all
firewall-cmd --get-services

# Open HTTP now and permanently
firewall-cmd --add-service=http
firewall-cmd --permanent --add-service=http
firewall-cmd --reload

# Open a custom TCP port
firewall-cmd --permanent --add-port=8080/tcp
firewall-cmd --reload
firewall-cmd --list-ports

Exam habit: Permanent rules do not always change the current runtime rules until reload. Runtime-only rules disappear after reboot.

SELinux

getenforce
sestatus
ls -lZ /var/www/html
ps -eZ | grep httpd

# Restore expected file labels
restorecon -Rv /var/www/html

# Find recent denials
ausearch -m AVC -ts recent
sealert -a /var/log/audit/audit.log

Use permissive mode briefly for diagnosis only when needed. The better fix is the correct context, Boolean, port label, or policy—not disabling SELinux.

Serve web files from a custom directory

# Install tools if needed
dnf install -y policycoreutils-python-utils

# Tell SELinux that this path contains web content
semanage fcontext -a -t httpd_sys_content_t "/srv/myweb(/.*)?"

# Apply the stored rule to existing files
restorecon -Rv /srv/myweb

# Verify labels
ls -ldZ /srv/myweb
find /srv/myweb -maxdepth 2 -printf '%p\n' | head

Allow a service to use a nonstandard port

# See which ports are already labeled for HTTP
semanage port -l | grep http_port_t

# Label TCP port 8088 for HTTP
semanage port -a -t http_port_t -p tcp 8088

# Verify
semanage port -l | grep http_port_t

SELinux Booleans

# Search useful switches
getsebool -a | grep httpd

# Read a description
semanage boolean -l | grep httpd_can_network_connect

# Enable now and make permanent
setsebool -P httpd_can_network_connect on

Core skill 8

Storage, partitions, LVM, file systems, swap, and fstab

A disk is raw land. A partition draws property lines. A file system builds shelves for files. LVM adds movable walls so storage is easier to resize.

Destructive command warning

The examples below use /dev/sdb and /dev/sdb1. Your practice disk may have a different name. Run lsblk -f and verify the blank disk before typing any write command.

Inspect storage

lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS,UUID
blkid
df -hT
df -ih
findmnt
pvs
vgs
lvs -a -o +devices

Create a GPT partition

# DANGER: confirm /dev/sdb is the blank lab disk
parted /dev/sdb --script mklabel gpt
parted /dev/sdb --script mkpart primary 1MiB 100%
partprobe /dev/sdb
lsblk /dev/sdb

Build LVM and XFS

pvcreate /dev/sdb1
vgcreate vgdata /dev/sdb1
lvcreate -L 2G -n lvreports vgdata
mkfs.xfs /dev/vgdata/lvreports

mkdir -p /reports
mount /dev/vgdata/lvreports /reports

pvs
vgs
lvs
df -hT /reports

Make the mount persistent

# Get the UUID
blkid /dev/vgdata/lvreports

# Back up fstab before editing
cp -a /etc/fstab /etc/fstab.bak

# Add a line like this, using your real UUID:
# UUID=1111-2222  /reports  xfs  defaults  0  0

# Test without rebooting
mount -a
findmnt --verify
findmnt /reports
Boot gotcha: A bad /etc/fstab line can send the system into emergency mode. Always run mount -a and findmnt --verify before rebooting.

Extend an XFS logical volume

# Add 1 GiB and grow the file system automatically
lvextend -r -L +1G /dev/vgdata/lvreports

# Verify both layers
lvs /dev/vgdata/lvreports
df -hT /reports

Gotcha: XFS can grow but normally cannot shrink. Ext4 can grow and can be shrunk only while unmounted, with careful steps. Plan before allocating all free space.

Create swap in LVM

lvcreate -L 1G -n lvswap vgdata
mkswap /dev/vgdata/lvswap
swapon /dev/vgdata/lvswap
swapon --show

# Add to /etc/fstab using UUID, then test
blkid /dev/vgdata/lvswap
swapoff -a
swapon -a
swapon --show

Scheduling, time, targets, and boot troubleshooting

Cron

Best for repeating calendar jobs.

crontab -e
crontab -l

# minute hour day month weekday
15 2 * * * /usr/local/bin/backup.sh

At

Best for one job at a future time.

echo "logger lab-at-job" | at now + 5 minutes
atq
atrm JOB_NUMBER

Systemd timer

Best when you want service logs, dependency rules, and missed-job handling.

systemctl list-timers --all
systemctl status dnf-makecache.timer

A systemd timer example

cat > /etc/systemd/system/lab-report.service <<'EOF'
[Unit]
Description=Write a small system report

[Service]
Type=oneshot
ExecStart=/usr/local/sbin/lab-report.sh
EOF

cat > /etc/systemd/system/lab-report.timer <<'EOF'
[Unit]
Description=Run the lab report each hour

[Timer]
OnCalendar=hourly
Persistent=true

[Install]
WantedBy=timers.target
EOF

systemctl daemon-reload
systemctl enable --now lab-report.timer
systemctl list-timers lab-report.timer

Time synchronization

timedatectl
systemctl status chronyd
chronyc sources -v
chronyc tracking

Systemd targets

systemctl get-default
systemctl set-default multi-user.target
systemctl isolate rescue.target
systemctl list-units --type=target

Gotcha: isolate changes the running system immediately and may stop services or your graphical session.

Boot repair thinking

  1. Read the exact error on the console.
  2. Check failed units with systemctl --failed.
  3. Read the current or previous boot journal.
  4. For mount problems, compare /etc/fstab, blkid, and lsblk -f.
  5. For changed boot settings, inspect GRUB configuration and kernel command-line values.
  6. After repair, run the verification command and reboot once more.
Recovery warning: Root-password recovery and bootloader editing differ by RHEL version, firmware mode, disk encryption, and security policy. Practice only in a disposable lab and compare the steps with the official documentation for the exact exam platform.

Automation

Shell and Python examples

Automation saves time, but only after you understand the manual steps. A good script checks inputs, stops on errors, prints clear messages, and returns a useful exit code.

Shell health check

#!/usr/bin/env bash
set -Eeuo pipefail

readonly WARN_DISK_PERCENT="${1:-80}"

echo "=== Host ==="
hostnamectl --static
cat /etc/redhat-release

echo
echo "=== Failed services ==="
if ! systemctl --failed --no-legend; then
  echo "Could not read systemd state." >&2
fi

echo
echo "=== File systems at or above ${WARN_DISK_PERCENT}% ==="
df -P -x tmpfs -x devtmpfs |
awk -v limit="$WARN_DISK_PERCENT" '
NR > 1 {
  used=$5
  gsub("%", "", used)
  if (used + 0 >= limit) {
    printf "WARNING: %s is %s%% full at %s\n", $1, used, $6
    found=1
  }
}
END {
  if (!found) print "No file systems crossed the warning level."
}'

echo
echo "=== Memory ==="
free -h

echo
echo "=== Network ==="
ip -brief address
ip route

echo
echo "=== SELinux and firewall ==="
getenforce
firewall-cmd --state 2>/dev/null || echo "firewalld is not running"

Python user audit

#!/usr/bin/env python3
"""List local interactive users and basic account facts."""

from __future__ import annotations

import json
import pwd
import subprocess
from dataclasses import asdict, dataclass


@dataclass
class UserRecord:
    name: str
    uid: int
    gid: int
    home: str
    shell: str
    locked: bool | None


def account_locked(username: str) -> bool | None:
    """Ask passwd whether the account password is locked."""
    result = subprocess.run(
        ["passwd", "-S", username],
        text=True,
        capture_output=True,
        check=False,
    )
    if result.returncode != 0:
        return None

    fields = result.stdout.split()
    status = fields[1] if len(fields) > 1 else ""
    return status in {"L", "LK"}


def main() -> int:
    users: list[UserRecord] = []

    for entry in pwd.getpwall():
        interactive = entry.pw_shell not in {
            "/sbin/nologin",
            "/usr/sbin/nologin",
            "/bin/false",
        }
        if entry.pw_uid >= 1000 and interactive:
            users.append(
                UserRecord(
                    name=entry.pw_name,
                    uid=entry.pw_uid,
                    gid=entry.pw_gid,
                    home=entry.pw_dir,
                    shell=entry.pw_shell,
                    locked=account_locked(entry.pw_name),
                )
            )

    print(json.dumps([asdict(user) for user in users], indent=2))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())

Judgment

Pros, cons, and common gotchas

ChoiceProConGotcha / better habit
Run as rootNo permission barriersOne typo can damage the whole systemUse a normal account and sudo for specific tasks
Disable SELinuxMay hide a denial quicklyRemoves an important security layerRead AVC logs; fix contexts, ports, booleans, or policy
Open firewall port broadlyFast connectivityLarger attack surfaceUse services/zones/sources and open only what is required
Use IP in fstab for NFSAvoids DNS dependencyHarder to change serversUse stable naming when DNS is reliable; test boot behavior
Mount by device nameEasy to typeDevice names may changeUse UUID or label in /etc/fstab
Use kill -9Stops a process immediatelyNo cleanup or graceful shutdownTry normal stop or TERM first
Use chmod 777Often makes access errors disappearGives everyone write accessFind the needed owner, group, ACL, or SELinux rule
Edit sudoers directlySimple file editSyntax error can lock out adminsUse visudo and a file in /etc/sudoers.d
Use old ifconfigFamiliar to older adminsMay not be installed and lacks modern detailLearn ip, ss, and nmcli
Allocate all VG free spaceMaximum space nowNo room for future LVs or growthLeave free extents unless the design requires all space
Copy commands without readingFast at firstPoor memory and hidden riskType commands, predict output, then verify
Make many changes at onceFeels efficientHard to know which change fixed or broke itChange one variable, test, and document

Learn by doing

Practice labs and mock tasks

Do each task on a clean lab system. Write the verification command before you begin. When finished, reboot and verify again.

Lab 1 — Files and text

Create /srv/reports/{incoming,processed}. Find every .log file under /var/log changed in the last day, save the list, archive it, and verify the archive contents.

Lab 2 — Users and groups

Create group analysts and users amy and ben. Add both to the group. Require password change every 60 days with a 7-day warning. Verify with id and chage -l.

Lab 3 — Shared directory

Create /srv/analysis owned by root:analysts. Members must create files that keep the analysts group. New files should not be readable by others. Test as two users.

Lab 4 — Sudo rule

Allow the analysts group to restart only httpd. Use a sudoers drop-in, validate it, and prove an analyst can restart httpd but cannot run an unrestricted root shell.

Lab 5 — Package and service

Install Apache HTTP Server, enable it at boot, create a test page, open the firewall, and verify locally and from Server B.

Lab 6 — SELinux content

Move the web content to /srv/site. Configure the web server and persistent SELinux file-context rule. Restore labels and verify enforcing mode remains active.

Lab 7 — Network connection

Create a static NetworkManager profile with a fixed address, gateway, DNS servers, and autoconnect. Reboot and verify address, route, DNS, and remote SSH.

Lab 8 — SSH keys

Configure key login from Server A to Server B. Copy a file using both scp and rsync. Verify ownership and checksum on the target.

Lab 9 — LVM storage

On a blank disk, create a GPT partition, PV, VG, 2 GiB LV, XFS file system, and persistent mount at /reports. Reboot and verify.

Lab 10 — Extend storage

Add 1 GiB to the reports LV and grow XFS online. Prove the LV and file system both increased.

Lab 11 — Swap

Create a 512 MiB swap LV, enable it now and at boot, then reboot and verify with swapon --show.

Lab 12 — NFS

Export a server directory to the lab subnet. Mount it manually on the client, then replace the manual mount with autofs. Verify read/write behavior.

Lab 13 — Cron and timer

Create one cron job and one systemd timer that write timestamps to separate files. Verify logs and persistence after reboot.

Lab 14 — Broken service

Make a safe syntax error in a disposable service configuration. Use status, journal, and the configuration test command to find and repair it.

Lab 15 — Full disk

Use a small disposable file system. Fill most of it with fallocate, find the large file, remove it, and prove the space returned.

Lab 16 — Broken fstab

On a snapshot, add a deliberately wrong noncritical mount, diagnose the failure with mount -a and the journal, then repair it before reboot.

Lab 17 — SELinux denial

Create a controlled denial, locate the AVC record, identify the correct context or Boolean, apply the smallest persistent repair, and retest.

Lab 18 — Shell script

Write a script accepting a service name as $1. It should report active/enabled state, recent errors, and listening ports, then return nonzero when the service is inactive.

Lab 19 — Documentation race

Without internet notes, use man, apropos, --help, and files in /usr/share/doc to solve five small tasks.

Lab 20 — Two-hour mock

Choose 10 tasks across all categories. Work without external notes. Reserve the last 20 minutes for verification, fstab checks, failed services, firewall, SELinux, and reboot testing.

What makes EX200 different?

EX200 is performance-based. You perform real system administration tasks instead of only choosing answers. Red Hat says internet access and personal notes are not available during the exam; product documentation supplied with the system is generally the reference you use.

That is why this site emphasizes command-line documentation, verification, persistence, and recovery from mistakes.

A snapshot is a safe rewind point

Before a storage, firewall, bootloader, SELinux, or network lab, shut down or pause the virtual machine and take a snapshot. Name it clearly, such as before-lvm-lab.

When the lab works, write the verification commands. Then restore the snapshot and repeat without notes. This turns a dangerous mistake into a useful lesson.
